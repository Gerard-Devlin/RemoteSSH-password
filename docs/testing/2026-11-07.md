# Local validation — 2026-11-07

[Testing guide](../testing.md) · [Compatibility](../compatibility.md)

This report covers the cumulative 0.3.x fixes and the 1.0.0 release candidate. No credential value was read or recorded during validation. Isolated fixtures use synthetic secrets; real-host acceptance used the normal masked-input and SecretStorage path without displaying saved values.

## Remaining acceptance

Windows and Intel Mac execution use their respective CI runners; cross-compilation alone is not counted as runtime compatibility. Full real-host acceptance is recorded below. Remote-SSH interoperability checks that do not exercise password memory remain tracked separately in the testing guide.

macOS keeps later keyboard-interactive prompts manual after a rejection or partial continuation. Reconnect to remember a replacement password. This avoids trusting server-provided authentication-list diagnostics.

## 0.3.1 reconnect regression

The macOS acceptance run exposed a stale-generation upgrade path: `bridge.json` in a new helper generation could name an older helper generation as `realSSH`. The later connection then created a nested wrapper while ASKPASS was scoped to the outer generation, so fixed-password prompts failed and OpenSSH exited after repeated attempts.

Setup now enumerates every existing `bridge-v2` generation and excludes all managed wrappers from real-OpenSSH recovery candidates. The native `ssh` launcher also follows old generation metadata directly to the real executable without executing nested wrappers, and falls back to ordinary OpenSSH when a chain is invalid or cyclic.

Regression results on macOS arm64 with Apple OpenSSH 10.5p1:

- TypeScript unit suite: 51 passed, including both Windows and macOS path cases for stale `bridge-v2` selection.
- Native unit and race suites passed; `go vet` passed.
- Windows x64 native tests and all four desktop helper executables cross-compiled successfully with CGO disabled. Windows runtime execution still requires a Windows runner.
- Real macOS OpenSSH loopback integration: 28 passed.
- English and Simplified Chinese compiled-extension suites: 19 passed in each locale.

## 0.3.2 Remote-SSH routing regression

Remote-SSH 0.128.0 on VS Code 1.145.2 can start a local-server process whose environment does not contain the extension host's `SSHPM_WINDOW_PIPE`. Version 0.3.1 treated that as an unavailable broker and passed the connection to ordinary OpenSSH, so Remote-SSH displayed its own password input.

The 0.3.2 regression suites remove `SSHPM_WINDOW_PIPE` entirely while retaining only the shared VS Code instance identity. The compiled extension still receives its own masked input, saves only after confirmed authentication, and reuses the saved password on reconnect. Native tests also cover focus selection between multiple windows in the same VS Code process and isolation from another instance.

Real macOS arm64 acceptance used two active Remote-SSH windows without reading or recording any credential value:

- Both windows started a 0.3.2 native broker and reported that the local authentication service was ready.
- A saved password authenticated one host through OpenSSH's `password` method.
- A saved fixed password authenticated the other host through `keyboard-interactive`.
- Neither active connection spawned Remote-SSH's native askpass prompt.

## 1.0.0 release candidate

The candidate closes the remaining release-readiness blockers without publishing a stable package:

- A stale non-empty `SSHPM_WINDOW_PIPE` may recover only to a current broker carrying the same VS Code instance identity. Without that identity it still fails closed. The integration suite covers both stale-route recovery and unknown-route isolation.
- Package verification now compares the complete VSIX inventory with an exact allowlist. Unexpected files fail even when they are outside known development directories. Environment files, logs, temporary files, coverage output, and OS metadata are also excluded.
- Automatic main-branch distribution remains preview-only. A stable Release requires a manual workflow dispatch that names the exact successful Platform checks run and selects `stable`. Existing Releases cannot be silently promoted or demoted.
- Marketplace metadata, README, compatibility, security, and release documentation no longer describe the candidate as a preview.
- The supported password-memory checklist in the testing guide is closed; extended Remote-SSH interoperability checks remain explicitly separate.

Validation evidence:

- `npm run check`: 51 TypeScript tests, 7 localization tests, 8 documentation/release-policy tests, and the native Go suite passed.
- Real OpenSSH loopback integration: 30 cases passed, including detached local-server routing, stale same-instance route recovery, cross-instance fail-closed behavior, exact SCP/SFTP, PTY, forwarding, rejection, cancellation, broker failure, and secret-file scans.
- English and Simplified Chinese compiled-extension suites: 19 cases passed in each locale.
- `go vet`, `go test`, and `go test -race` passed locally. `actionlint` accepted both GitHub Actions workflows.
- GitHub Platform checks passed on Windows x64, macOS arm64, and macOS Intel, including real OpenSSH integration, bilingual compiled-extension tests, native package architecture checks, and exact-inventory verification.
- `npm audit` found zero vulnerabilities.
- The isolated Go test server upgrades `golang.org/x/crypto` from 0.37.0 to 0.58.0 and `golang.org/x/sys` from 0.32.0 to 0.49.0. This clears the Dependabot advisories for test fixtures once the candidate reaches the default branch; no affected package is present in the VSIX.
- `govulncheck` found no code-reachable vulnerabilities in the production helpers or test server. One module-level advisory remains unreachable by this code.
- Apple Silicon real-host acceptance covered two simultaneous Remote-SSH windows, saved direct-password authentication, saved keyboard-interactive authentication, broker readiness, and absence of Remote-SSH native askpass prompts.

Known supported-build limits remain intentional: Windows requires the pinned OpenSSH 9.5p2 hash, and Remote-SSH 0.128.0 is the inspected integration version. Unknown builds fall back to ordinary OpenSSH rather than reading saved credentials.
