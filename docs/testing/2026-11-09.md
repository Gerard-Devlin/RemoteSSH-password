# VS Code compatibility and release hardening — 2026-11-09

[Testing guide](../testing.md) · [Compatibility](../compatibility.md)

This report covers the 1.1.0 VS Code compatibility expansion and the 1.2.0 Windows OpenSSH/uninstall hardening candidate. No user credential was read or recorded.

## Change

- The extension manifest now declares VS Code `^1.73.0`.
- TypeScript compiles against the exact `@types/vscode` 1.73.0 release.
- A release-policy test keeps the manifest engine, lockfile, API types, and compatibility documentation aligned.
- A real VS Code 1.73.0 compatibility smoke test activates the development extension, checks `vscode.l10n`, and verifies that all five management commands are registered.
- Microsoft Remote-SSH keeps its own editor requirement. VS Code is expected to resolve the newest Remote-SSH release compatible with the running editor.

## Windows OpenSSH profiles

- `native/windows-openssh.json` is the single allowlist for the Windows system 9.5p2 build and official Win32-OpenSSH 9.5p1, 9.8p2, and 10.0p2 archives.
- Each profile binds an exact `ssh.exe` SHA256 to a version marker and source-line LogVerbose callsite set. TypeScript selection and the embedded Go runtime both reject unknown hashes or profile/filter mismatches.
- The Windows CI matrix downloads each official archive, verifies both archive and executable SHA256 values, confirms `ssh -V`, and runs real OpenSSH loopback plus compiled-extension tests against that exact binary.
- Local archive verification downloaded all three official archives and matched their archive and `ssh.exe` hashes. Windows execution is exercised by the Windows runner rather than the local macOS host.

## Uninstall recovery

- A registered `vscode:uninstall` Node hook restores only unchanged extension-owned `remote.SSH.path` and `remote.SSH.useLocalServer` values.
- The hook uses a password-free snapshot, preserves JSONC comments and unrelated settings, leaves later user edits untouched, and disables the retained bridge.
- Tests execute the bundled production `dist/uninstall.js`, not only the TypeScript source helper.

## Verification

- `npm run check`: 57 TypeScript tests, 7 localization tests, 10 documentation/release-policy tests, and the native Go suite passed.
- Real macOS Apple Silicon OpenSSH loopback integration: 30 cases passed.
- English and Simplified Chinese compiled-extension-entry suites: 19 cases passed in each locale.
- Real VS Code 1.73.0 on macOS arm64: extension activation, `vscode.l10n`, and five command registrations passed.
- `npm audit`: 0 vulnerabilities.
- Windows x64, macOS arm64, and macOS x64 candidate VSIX files passed exact 39-entry inventory and platform-architecture verification.

## Remaining acceptance

The 1.73.0 host test proves the extension API floor and startup activation. A complete password-memory connection with an older Remote-SSH release on VS Code 1.73.0 has not yet been exercised. Windows and Intel Mac low-version hosts are also covered by CI configuration rather than this local macOS arm64 run. The real VS Code post-uninstall lifecycle is exercised by the bundled-hook test and Windows CI packaging; a manually observed editor restart after marketplace uninstall remains an acceptance check.
